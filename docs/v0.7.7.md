# Rust Explorer 0.7.7

2026-10-21 · Windows 10/11 x64 · [下载与校验文件](https://github.com/Mingcodeingmiao/rust-explorer/releases/tag/v0.7.7)

本版本从“右键菜单性能优化”开始累积：把系统菜单重新放回应用进程内，避免每次右键都新起辅助进程；修复悬浮卡片越界和其他程序抢焦点的问题；并补上快速访问与回收站地址栏的特殊处理。0.7.6 已发布的内容保持不变。

## 修复

- **系统右键菜单重新走进程内热路径**：0.7.6 的“系统操作可取消”把菜单请求也送进一次性 helper，导致每次右键都新起进程并重新加载 Shell 扩展（冷启动约 250 ms，扩展较多时接近 1 秒），0.7.5 的进程内热路径被绕过。现在只有菜单请求走进程内、带窗口 owner 的路径，其他系统操作仍保留一次性 helper 与停止/强行停止能力，右键回到 40–80 ms 的常态。
- **悬浮卡片不再越界**：文件悬浮卡片和标签页悬浮卡片改为应用窗口的附属窗口（owner = 主窗口），去掉置顶样式，只浮在本窗口之上，不会盖住其他程序；文件卡片定位在指针右下并夹紧在主窗口矩形内，应用不在前台、指针移出窗口、菜单打开或窗口失去激活时立即隐藏；标签页卡片底边与主窗口上沿齐平，窗口贴屏幕顶部时改挂到标签下方，多显示器下水平夹在窗口左右边界内。两者字号与内边距统一按“界面缩放 × 系统 DPI”计算，缩放变化时重建。
- **右键已选中的文件/文件夹**：已经选中的项目，右键它组件上的任意位置都能打开该项目自己的右键菜单；此前必须点中图标、文件名或元数据才算命中。未选中的项目仍只按图标/文件名/元数据区域命中，点它的空白处继续显示背景菜单并取消选择，不会误抢其他项目的选中状态。
- **地址栏特殊位置**：快速访问和回收站显示的名称（`快速访问`、`此电脑\回收站` 以及回收站内的子文件夹）回车后直接回到该位置，不再当成磁盘路径而无法打开；重命名“此电脑”后同样识别（不依赖缓存里的电脑名）。回收站内的文件夹在地址栏和标题中只显示自身名称，不再显示删除前的完整路径。当前目录下确实存在的同名项仍优先打开真实路径。

## 界面调整

- **文件夹选项新增“高级”页**：清空缓存、默认文件夹（实验性）、高性能模式开关和界面资源统一放在“高级”里，“常规”“查看”只保留日常设置。清空缓存从 `…` 选择菜单移除，现在只有高级页这一处入口。
- **“启动时打开”改为一行**：主文件夹、此电脑、快速访问三个按钮并排放置，不再各占一行。

## 导航

- **不可用时按钮置灰**：前进、后退没有对应历史，或“向上”在当前虚拟页面不可用时，按钮灰显、点击无效果。
- **返回时恢复现场**：前进/后退/向上回到某个目录时，恢复该目录之前的滚动位置并重新选中当时操作的项（`↑` 会选中刚离开的那个文件夹），与资源管理器一致；历史状态按标签页分别保存。若项目已被删除或重命名，则只恢复滚动位置。
- **点击地址栏路径同样选中来路**：在 `C:\Windows\system32\drivers` 点击地址栏上的 `Windows`，会打开 `C:\Windows` 并自动选中 `system32`；点击驱动器或“更多”里的隐藏路径也遵循同样规则。
- **鼠标侧键**：侧键 1（后退）/ 侧键 2（前进）直接执行前进后退，与按钮及 Alt+←/→ 行为相同。

## 性能与缓存

- **图标缓存按 7-Zip 的方式共享**：阅读 7-Zip 源码（`SysIconUtils.cpp`、`PanelItems.cpp`、`Panel.cpp`）确认它的图标只是系统 image list 的索引，按扩展名/属性用 `SHGetFileInfoW(..., SHGFI_USEFILEATTRIBUTES | SHGFI_SYSICONINDEX)` 解析（多数情况不打开文件），列表按索引绘制。本程序据此把图标请求规范化：普通文件夹在 helper 里只做一次 desktop.ini 探测（约 10 µs/个），没有自定义图标就共用同一个 “folder” 缓存条目，不再为每个文件夹生成一张 PNG；带 desktop.ini 自定义图标的文件夹（例如 `C:\Windows\Offline Web Pages`）仍按路径解析真实图标。扩展名图标、驱动器根、便携设备根以及 exe/lnk/url/ico/cur 的规则不变——驱动器根（含网络驱动器、可移动盘、RAM 盘）**永不归一**，始终使用带驱动器类型与覆盖标记的真实图标。图标批次同时从 8 项提高到 32 项，超时随批次数增长，减少滚动大目录时的 helper 启动次数。
- **`.url` 在图标视图不再空白**：中等图标、大图标与内容视图原本把 `.url` 当成缩略图请求，而 Shell 对 Internet 快捷方式只能返回通用空白页；现在 `.url` 不再进入缩略图管线，改由图标管线（STA 套间 + 图标句柄）显示真实图标。`.lnk` 仍会预览目标的缩略图，照片/文档快捷方式不受影响。
- **快捷方式/互联网快捷方式图标**：`.url`（含 `IconFile=` 的 Steam 快捷方式）和 `.ico`/`.cur` 的图标由 COM 处理器提供，且只以图标句柄形式返回——它们在图库（image list）里的索引指向的是另一张通用图标。原先图标 helper 没有 COM 套间、且大图标时按索引从图库取图，于是这些文件显示成空白页。现在 icon helper 会申请 STA 套间（线程已有套间时不改变），并对 `.url`/`.ico`/`.cur` 直接使用返回的图标句柄；`.lnk` 在索引为 0（目标图标无法进图库）时同样回退到句柄。图标缓存另起 `icons-v2` 目录，避免复用旧版生成的错误位图。
- **大目录列举提速约 6 倍**：目录扫描改为单次 `FindNextFileW`，名称、属性、大小、时间与重解析标记一次取回，不再对每个项目做一次路径 stat、也不再对每个联接点额外查询。`C:\Windows\WinSxS`（16306 项）实测：扫描 325 ms → 约 32 ms。
- **排序提速**：自然排序先为每个条目生成排序键（数字段编码为“标记 + 长度 + 数字”），按字节比较索引后原地置换，避免每次比较都做小写转换与逐字节比较；WinSxS 的名称排序 57 ms → 约 30 ms。同时修正自然排序的一个旧问题：`a1` 与 `a01` 视为同一个数字（此前会按字符串长度排错），`a1` 仍正确排在 `a1b` 前面。
- **缩略图工作线程上限 4**：实测 2/4/8 线程生成 12 个文件夹预览分别为 13.7/10.2/9.9 ms，超过 4 个线程没有收益，而每个线程都要独占一个 helper 进程；因此线程数取 `min(核心数 − 2, 4)`，避免进入大目录时同时启动十几个进程抢 CPU。
- **文件夹预览更快命中缓存**：文件夹的缓存键不再每 30 秒变化，只用文件夹自身的修改时间失效（只有 `.lnk`/`.url` 仍保留 30 秒时间桶）；客户端命中缓存也不再经过 helper——索引文件名已包含完整键，已缓存的缩略图无需 IPC。因此重开窗口、来回切换目录、滚动回去都能立即显示文件夹预览，只有文件夹内容变化后才重新合成。
- **慢预览不再被误杀**：文件夹与便携设备的生成预算放宽到 3 秒 / 4 秒（普通文件仍 800 ms），避免大型文件夹合成到一半被判定超时、杀掉 helper 再从头重做。视口稳定等待也从 100 ms 缩短到 60 ms。
- **缩略图多线程生成**：按“核心数 − 2”启动生成线程（至少 1 个），每个线程使用自己隔离的缩略图 helper；任务统一排队，依次交给空闲线程（第 1 个给线程 1、第 2 个给线程 2、第 3 个回到线程 1……）。每次滚动或切换目录都用当前可见项重建队列，因此**先出当前屏幕上的缩略图**，滚走的任务立即取消。
- **MTP 设备缩略图也会缓存**：手机等便携设备的照片/文件夹按同样的索引结构缓存到本地，重开窗口或刷新不再重新向设备取图。设备项一次只允许一个线程生成（同一台手机不支持并发缩略图会话），本地文件仍并行生成。
- **MTP 设备不再闪一下**：最近一次枚举到的便携设备保留 60 秒，并随快照一起发布；`--shell-devices` 超时也保留上次结果，新窗口打开时不会再先“没有手机”再补出来。设备真正断开后，最多约一分钟内的下一次枚举会让它消失。
- **缩略图缓存按内容去重**：缩略图 PNG 以自身字节的 SHA-256 命名（`<sha256>.png`），同一张图只保存一份；每个项目只保存一个很小的索引（键、图片名、链接角标/照片尺寸等装饰信息）。重复内容因此不再各存一份，节省大量空间。
- 旧版按项目命名的 PNG 缓存在升级后自动清理（`thumbnails-v6`）；“清空缓存”同时清理新旧目录。共享图片上限 4096 个 / 128 MiB、索引上限 8192 个，超出按最久未用淘汰；图片被淘汰后对应项目重新生成，内容相同仍会回到同一个文件名。

## 维护约束

- 菜单请求必须保留窗口 owner 并在应用进程内显示，不能并入“一次性 helper + 可取消”路径。`src/shell.rs::execute_controlled` 顶部有醒目警告注释与 `debug_assert`，并新增回归测试 `context_menus_keep_an_owner_and_stay_out_of_the_one_shot_helper`；`CONTRIBUTING.md` 同步记录该约束，避免后续改动再次合并这两类请求。

## 使用与升级

1. 退出正在运行的旧版本，完整解压 `RustExplorer-0.7.7-windows-x64.zip` 到独立目录。
2. 对照同页 `SHA256SUMS.txt` 校验 ZIP。PowerShell 可运行 `Get-FileHash .\RustExplorer-0.7.7-windows-x64.zip -Algorithm SHA256`。
3. 运行 `rust-explorer.exe`。发布包为 Windows x64 GNU 优化构建，附运行时 DLL、可选 Everything SDK DLL、许可证和说明文档，无需浏览器运行时。程序未签名。
4. 若已启用实验性默认文件夹关联，请先通过旧版恢复系统默认，再迁移到新版并重新启用，保留备份及恢复文件。参见[恢复说明](default-folder-browser.md)。不要直接删除仍被关联的旧路径。

## 验证与边界

- 格式检查、122 个核心测试、1 个独立快捷方式集成测试、全目标编译检查通过；1 项交互删除测试按原规则跳过。GitHub Windows CI 的结果可在关联发布 PR 查看。
- 大目录数据为本机实测（`C:\Windows\WinSxS`，16306 项，NTFS 本地磁盘）；机械硬盘、网络位置与占用大量内存时的表现会不同。与 7-Zip File Manager 相比，它只按文件类型复用系统图标、不做缩略图和文件夹合成，所以在大目录下天然更快；本程序保留资源管理器的预览语义，用缓存与并发上限控制开销。图标方面两者现在同为“按类型/属性复用系统图标”，但 exe、快捷方式仍按项目解析真实图标（7-Zip 默认显示类型图标），目录里可执行文件很多时会比 7-Zip 慢一些。
- 自定义文件夹图标（`desktop.ini`）仍会显示：普通文件夹共用系统文件夹图标，带自定义图标的文件夹按路径解析；每屏多出的开销只是每个可见文件夹一次 desktop.ini 探测（约 10 µs）。
- 缩略图并发数是 `min(核心数 − 2, 4)`，并发时每个线程各用一个隔离 helper 进程；低内存机器若觉得占用偏高可反馈。
- 文件夹预览以“文件夹自身的修改时间”失效：新增/删除/重命名子项会触发重做，仅修改某个子文件的内容不会。需要强制重做时可用“文件夹选项 → 高级 → 清空缓存”。
- 菜单耗时为本机实测（同一台机器、同一批 Shell 扩展），不同扩展组合、冷热启动和 Windows 版本会有差异；`RUST_EXPLORER_MENU_TRACE=1` 可输出 `menu: in-process …` 轨迹用于自查。
- 悬浮卡片的隐藏依赖窗口激活与前台判断；被其他程序强制抢焦点时以实际显示为准。
- 地址栏特殊名称按中英文显示名匹配（`快速访问`/`Quick Access`、`回收站`/`Recycle Bin`），其他系统语言的显示名需按实际名称输入；回收站内的条目仍只能回到回收站，不能恢复到原位置。
- 见[已知边界](../KNOWN_ISSUES.md)与[后续计划](../ROADMAP.md)。

## English summary

0.7.7 collects the work that started with the context-menu latency fix: UI Shell menus are displayed in the application process again with their window owner, so a right click no longer spawns a helper process and cold-loads Shell extensions (about 250 ms, near 1 s with many extensions) instead of the 40–80 ms in-process path. Other tracked Shell operations keep their one-shot helper and stop/force-stop controls, and a warning comment, a `debug_assert` and a regression test keep the two request classes apart. Hover cards are owned by the application window, never topmost, clamped inside it, and hidden when the window is inactive, the pointer leaves, or a menu opens; tab cards sit flush with the window top and flip below it when the window touches the screen edge. An already selected item answers a right click anywhere inside its own cell, while an unselected one still requires an icon, name or metadata hit so the empty part of a row keeps the background menu. Folder options gained an **Advanced** tab (cache clearing, experimental default-folder association, high-performance toggle, UI resource source), and the three "open at startup" buttons on the General tab now share one row. Cache clearing was removed from the `…` menu and lives only in that tab. Back/forward/up are greyed out when unavailable and restore the previous scroll position and selection (↑ selects the folder just left), the state is kept per tab, and the mouse side buttons navigate back and forward. Clicking an ancestor in the address bar selects the folder you came from (from `…\system32\drivers`, clicking `Windows` opens it with `system32` selected). Thumbnail PNGs are now stored under the SHA-256 of their bytes, so identical images share one file; a small per-item index keeps the key-to-image mapping and the link/photo decorations, and the previous per-item PNG cache is removed on upgrade (4096 images / 128 MiB and 8192 indexes are the caps). Folder previews keep one cache key per folder (invalidated by the folder's mtime instead of a 30-second bucket), cached entries load without a helper round trip, slow folder/device previews get 3–4 s instead of 800 ms, and the settle delay is 60 ms. Preview generation runs on one worker per core beyond the two kept free (cores − 2), each with its own isolated helper, and the queue is rebuilt from the visible rows on every scroll so on-screen items come first. Portable-device photos and folders are cached the same way and generated one at a time (a phone rejects concurrent thumbnail sessions), and the last device enumeration is kept for a minute so opening a window no longer makes a connected phone vanish and reappear. The address bar now resolves the displayed names of Quick Access and the Recycle Bin — including after This PC is renamed and for folders inside the bin — back to their location instead of failing as a disk path. The unsigned Windows x64 GNU package includes runtime DLLs, optional Everything SDK, licenses and SHA-256 checksums.
