# Rust Explorer 0.7.5

2026-10-20 · Windows 10/11 x64

本版本在 0.7.4 的基础上，集中修复**右键菜单**的可靠性、**新窗口打开**的显示方式，并做了一轮**性能优化**。功能入口不变。

## 右键菜单

### 根因：菜单原本由另一个进程显示

上一版菜单由独立 helper 进程显示。实测在该环境下，**菜单弹出后 10–20 ms 就被系统取消**（日志：`WM_ENTERMENULOOP` → UAH 测量 → `WM_CAPTURECHANGED` → `WM_EXITMENULOOP`，且没有来自我们自己的 `WM_CANCELMODE`/`WM_ACTIVATEAPP`；`GetLastError=183`）。同期可以看到 **Rust Explorer 主窗口被取消激活、任务栏按钮变成非活动外观**——菜单是"另一个进程的窗口"抢走了前台，这是整类问题的来源。

### 现方案：菜单在应用自己的进程内显示

- 菜单在应用进程内构建并显示，owner 为应用窗口；应用保持前台/活动，**任务栏按钮不再变灰**。
- owner 窗口是**主窗口的子窗口**（`WS_CHILD`），与主窗口共享激活，菜单显示期间**主窗口不会失去 DWM 激活边框（阴影）**；同时不再调用 `SetForegroundWindow`/`SetActiveWindow`/`SetFocus`。
- 菜单不再被"瞬间取消"：进程内显示时 `WM_ENTERIDLE` 持续出现（菜单正常等待输入），稳定存活直到用户操作。
- 构建仍发生在 GPUI 的后台线程（该线程初始化 STA），**UI 线程不被阻塞**；菜单仍是真实的 Windows Shell 菜单（`IContextMenu`/`QueryContextMenu`）。
- 代价：第三方 Shell 扩展现在运行在本应用进程内（与 Explorer 相同）；文件操作、缩略图、预览等重活仍由隔离 helper 执行。

### 手势与可靠性

- **防抖只统计"按下→抬起"的位移**（阈值 12px，系统拖动阈值约 4px）。松开后指针继续移动（例如菜单还在构建时把鼠标移开）**不再影响**菜单弹出；超过 12px 才视为右键拖动。
- 命中"按下触发"的位置（空白区、导航树等）会**先等右键松开**再弹出（最多 700 ms，期间照常泵消息），松手后再等 30 ms，避免那次 `WM_RBUTTONUP` 落到刚出现的菜单上。
- **悬浮提示不再干扰菜单**：文件悬浮卡片改为**独立原生窗口**（`WS_EX_TRANSPARENT` + `WM_NCHITTEST=HTTRANSPARENT` + `MA_NOACTIVATE`，不参与命中测试与激活），按 Explorer 习惯放在**指针右下方**（+14 / +22 px，越界自动翻转并做屏幕内钳制），打开菜单时主动收起。
- 悬浮卡片的字号与内边距按 **`rem_size × 显示器 DPI 缩放`** 计算（此前漏乘 DPI，125%/150% 下偏小），缩放变化时重建卡片。
- **菜单结果不带尾部换行**：应用侧用精确字符串匹配（`command:paste`、`rename`、`properties`、`refresh`、`command:quick-pinned`），此前多余的 `\n` 会让粘贴、在新标签页/新窗口打开、删除、快速访问刷新**静默失效**。

### 会阻塞或弹模态框的动词

- `delete` / `paste` 改由**应用自身实现**（`command:file-delete` / `command:file-paste`，隔离 helper + 自己的对话框，与 Delete 键、Ctrl+V 一致），不再因 `SEE_MASK_NOASYNC` 卡住菜单任务（此前表现为停在"正在处理系统操作"）。
- `format` / `print` / `share` / `burn` 这类**自带模态对话框**的动词交给**分离的 helper 进程**（`InvokeVerb` + `ShellExecuteExW`），应用立即返回；`SEE_MASK_FLAG_NO_UI` 只屏蔽 Shell 自身的错误弹窗。
- 其余第三方动词仍走 `IContextMenu::InvokeCommand`，进程内已去掉 `SEE_MASK_NOASYNC`，不会长时间阻塞。
- **"格式化"改走管理员进程**：`HKCR\Drive\shell\format` 并不存在（它不是注册表动词，而是 Shell 驱动器视图内置命令），`ShellExecuteExW("format")` 找不到它。现在该动词**以管理员身份重启自身**（`runas` + `--format-drive <盘符>`），新进程调用 `SHFormatDrive` 显示真正的格式化对话框。
- 移除了"120 ms 内被取消就自动重显（最多 3 次）"的重试——那是为跨进程激活竞争兜底，现已无必要，菜单只弹一次。

## 新窗口打开

- **按目录计算显示方式**：列出一个文件夹时统一按"**配置里该文件夹保存的视图** → **程序内置默认**（此电脑/便携设备=平铺，普通文件夹=详细信息）"解析；新窗口、同一窗口内跳转、切换标签页都走这套规则，不再依赖另一个窗口当时的状态。
- 修复的具体问题：新窗口原先**先用默认文件夹（此电脑）构造**，随后把标签换成目标文件夹（如 `C:\`）却**没有重新计算视图**，于是沿用了此电脑的"平铺 + 按类型分组"，表现为"驱动器新窗口的显示模式不对"。现在换标签后会重新解析视图，并按文件夹类型重置分组（此电脑按类型分组，普通文件夹不分组，回收站固定详细信息，便携设备平铺）。
- 新窗口之间只传递**目标目录**这一个参数。

## 性能

- **菜单构建**：进程内构建，首次（冷）约 250–300 ms，之后（热）约 40–80 ms；逐项 `GetCommandString` 走缓存，省去每次菜单中重复两遍的查询。
- **新窗口共享磁盘/快速访问缓存**：所有窗口在同一进程内，因此使用**进程内共享缓存**（磁盘快照 20 s TTL、快速访问列表 20 s TTL）。第一个窗口负责采样，之后打开的窗口直接复用，侧边栏瞬时出现——不再重新枚举磁盘、也不再另起 `--quick-access` helper。
- 快速访问固定/取消固定完成后**立即刷新**列表，不再等 15 秒节流；状态栏给出对应提示。
- **可选诊断**：`RUST_EXPLORER_MENU_TRACE=1` 会把菜单生命周期与"视图解析/重算"记录到 `%TEMP%\rust-explorer-menu.log`（含 `view: resolved …`、`view: navigate …`、`view: rebuild_rows …`），默认关闭。

## 验证及边界

- 在 Windows 11 26100 + GNU 工具链（MSYS2 UCRT64 GCC 16.2.0）下构建与测试；单元测试 95 项通过、1 项需交互的测试跳过，另有 1 项集成测试单独成进程运行。
- `scripts/check.ps1` 增加一步集成测试：Shell 快捷方式解析会初始化 COM 套间，而单元测试共用同一线程，若在那里 `CoUninitialize` 会让紧随其后的测试以 `STATUS_ACCESS_VIOLATION` 崩溃，因此该测试移到 `tests/shortcut_targets.rs` 独立进程执行。
- 菜单延迟与已安装的第三方 Shell 扩展数量相关；首次菜单仍需承担一次扩展加载成本。
- 第三方 Shell 扩展现在与被调用的动词同进程运行（与 Explorer 相同）；若某个扩展崩溃会影响本程序，这是换取菜单可靠性的取舍。

## English summary

0.7.5 fixes the context menu and the way new windows are opened, and trims menu/window startup costs. Context menus are now built and shown **inside the application process**, owned by the application window: the previous helper process lost activation to the app (its taskbar button flipped to the inactive look) and Windows cancelled the menu 10–20 ms after it appeared. The in-process owner is a child window, so the main window keeps its DWM active frame, and the app never claims the foreground. The right-click debounce now measures travel strictly between the press and the release, so moving the pointer while the menu is still being built no longer cancels it; the hover card became a click-through native window placed below-right of the pointer and is DPI-aware. Menu results no longer carry a trailing newline (which silently disabled paste, open-in-new-tab/-window, delete and the Quick Access refresh), `delete`/`paste` are routed to the application's own implementations, dialog verbs (`format`/`print`/`share`/`burn`) run in a detached helper, and the drive "Format" command relaunches elevated and calls `SHFormatDrive`. A folder is now listed the way the settings resolve it (saved per-folder view, else the built-in default) instead of inheriting whatever the source window showed, and drives/Quick Access are cached per process so new windows open instantly.
