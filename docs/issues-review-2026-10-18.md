## #9：GB2312 文本预览乱码

**反馈环境：** Rust Explorer 0.6.3，Windows 11 Pro for Workstations 24H2 64 位。报告称任意 GB2312 文本预览即可复现，其它编码未测试。

**实际问题：** 中文文本被当作其它编码解释，导致右侧预览无法正常阅读；这不是要求修改文件本身的编码。

**源码证据：** `src/preview.rs` 的 `text()` 已处理带 BOM 的 UTF-16 LE/BE；其它内容经二进制检查后直接使用 `String::from_utf8_lossy`。没有 GB2312/GBK 解码分支。该代码仍存在于当前工作区，因此旧版本反馈仍值得修复。此结论来自源码，今晚没有重新运行编码样本。

**建议处理：**

1. 优先识别 BOM，再严格尝试 UTF-8；失败后才考虑 GBK/GB2312 兼容解码，避免把正常 UTF-8 误判。
2. 对无法可靠判断的内容保留明确的编码选择或提示；不要宣称能自动识别所有编码。
3. 保留现有读取上限、二进制拒绝和预览截断机制。读取上限切在多字节字符中间时，也应避免制造整份文件的错误编码判断。

**验收：** 自建 GB2312、GBK、UTF-8（有/无 BOM）、UTF-16 LE/BE 样本；核对中文、英文、换行、空文件、截断边界和二进制文件。仅预览，不改写源文件。

## #8：窗口顶部缩放命中区域不易触发

**反馈环境：** 0.6.4，Windows 11，未提供 DPI、应用缩放、窗口状态。用户描述顶部不易进入调整尺寸状态，而左右、底部正常。

**复现目标：** 普通窗口状态，缓慢移动到顶部边框与顶角，比较左右/底部的鼠标指针变化及拖动成功范围。最大化时应单独验证，不能把最大化窗口不能普通拉伸当作相同问题。

**已知与推测：** 当前窗口在 `src/ui_extras.rs::open_explorer()` 使用 GPUI 的透明标题栏选项。可能涉及标题栏拖动区域、客户端控件对上边框的覆盖、系统非客户区命中或 DPI 换算；这些均是待验证方向，尚未证明为根因。不要直接增加整条顶部拖动区而影响标签点击。

**建议排查：**

1. 先复现并测量顶部与其它边框的实际可命中范围。
2. 检查标签栏与窗口标题栏的事件区域，以及 GPUI Windows 窗口命中处理。
3. 必要时再调整命中区域，优先沿用系统窗口缩放逻辑。

**验收：** 普通窗口的上、下、左、右、四角；100%/175% DPI 或可获得的不同 DPI 环境；应用缩放；最大化再还原。顶部应容易进入缩放状态，标签切换、标题栏拖动、双击最大化与三个窗口按钮仍正常。不重复验证用户已确认可用的边缘贴靠作为本问题的替代验收。

## #10：设置为默认文件浏览器

**反馈诉求：** 无须先打开 Rust Explorer，即可从系统操作进入；正文同时出现“默认文件浏览器”和“双击文件”，两者的接管范围尚不明确。

**现有能力：** `src/ui.rs::Explorer::new()` 已读取第一个命令行参数，并接受目录或虚拟位置。没有在该入口看到对普通文件参数的同等处理。已有目录参数入口不等于已经完成系统默认浏览器注册。

**建议先定义范围：**

- 文件夹/驱动器的打开是否交给 Rust Explorer。
- 传入普通文件时，是定位并选中、调用关联应用，还是执行其它行为。
- 用户希望的是新增“用 Rust Explorer 打开”入口，还是更改默认打开行为。可先实现可撤销的显式入口，再决定默认接管。

**实施要求：** 用户主动开启；优先考虑当前用户范围；记录并恢复旧配置；支持取消和卸载后的恢复；不要接管所有文件扩展名。避免 Rust Explorer 自己调用系统打开时产生递归启动。具体 Windows 注册机制实施前再核对官方资料，本次没有修改注册表。

**验收：** 带空格/中文的安装路径与参数；文件夹、驱动器、普通文件、失效路径；重复启停；恢复原配置；程序被移动或删除后的行为；避免打开循环。涉及实际系统关联变更时，应先给用户审阅具体方案。
