# 小窗口三级菜单无法选择：修复记录

## 问题

窗口可用空间不足时，「更多 → 查看 → 显示」的三级菜单反向展开，覆盖了第一级菜单。
之前仅整个弹出层阻挡主界面鼠标事件，每个菜单面板没有阻挡其后面的其他菜单面板。底层行仍会收到鼠标移动，改变或关闭子菜单，随后点击误触底层命令。

使用独立测试配置、缩短窗口并将应用缩放到 120%，复现了相同重叠布局。修复前点击「项目复选框」实际触发底层「全部选择」，复选框设置保持关闭。

## 修改

- 每层菜单面板单独阻挡后方的鼠标悬停、点击和滚轮命中，保留子菜单内部正常交互。
- 菜单最大高度同时受当前位置到窗口底部的可用空间约束；内容超出时在面板内部滚动。
- 未更改菜单命令本身和系统原生菜单。

## 验证

- 桌面调试构建、全目标编译检查通过。
- 在与修复前相同的重叠菜单布局下，逐一点击四项，验证界面变化及独立配置文件：
  - 项目复选框：false → true，文件列表出现复选框，没有选中所有文件。
  - 文件扩展名：true → false，alpha.bin / beta.bin 隐藏扩展名。
  - 隐藏的项目：false → true，重新打开菜单显示勾选。
  - 紧凑视图：false → true，文件行及侧栏行随之变紧凑。
- 仅修改临时测试配置；没有修改日常配置、删除文件或更改系统关联。
