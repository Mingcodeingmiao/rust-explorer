# Rust Explorer 0.7.6

2026-10-20 · Windows 10/11 x64

本版本聚焦文件视图里的**快捷方式图标**：`.url` 现在有图标预览，快捷方式的预览图带链接箭头，自绘箭头尺寸与 Explorer 的比例对齐。

## .url 图标预览

`.url` 指向的是网址而非文件。此前缩略图流程会把它当作快捷方式去解析目标路径，得到的是 `https://…`，随后取元数据失败，最终返回"文件不支持缩略图"，tile 上只能退回小号类型图标。

现在的处理：

- 只有 `.lnk` 才解析目标（目标是真实文件，用目标自己的缩略图/图标）；
- `.url` 不再解析，直接把 **.url 文件自身**交给 Shell 取图标——Windows 有站点图标时给站点图标，否则给"网页快捷方式"图标。

## 快捷方式预览图带链接箭头

`IShellItemImageFactory` 只返回图像本身，**不会叠加** Shell 的快捷方式覆盖图标，所以 `.lnk`/`.url` 的预览图看起来和普通文件一样。现在对快捷方式的预览图统一在左下角合成链接箭头：

- 角标为白色方块 + 蓝色箭头，箭头指向**左上**（与 Windows 覆盖图标一致）；
- 角标边长 = 图像短边 × 28%；
- 处理放在 `native_preview::with_link_badge`，直接写入 RGBA，不依赖额外的图像库。

## 自绘链接徽标尺寸

文件视图里"链接类型但 Shell 没给覆盖图标"的条目由程序自绘徽标（`visual::link_badge`）。尺寸改为按图标尺寸的比例计算：

| 显示方式 | 图标尺寸 | 徽标边长 |
|---|---|---|
| 超大图标 | 154 | 27.5% → 42px |
| 大图标 | 102 | 25% → 26px |
| 中等图标 | 64 | 15.6% → 10px |
| 平铺 / 列表 / 详细信息 / 小图标 | 40 / 16 | 保持原尺寸不变 |

> Shell 没有"单独取覆盖图标位图"的 API（覆盖图标只能随完整图标一起取得），因此箭头仍为自绘；尺寸比例按 Explorer 的观感对齐。

## 缓存

缩略图与图标缓存版本提升为 `native-v6-r4` / `thumbnails-v5`，避免旧缓存继续返回没有箭头的图片。

## 验证及边界

- 实测 `C:\Users\rei\Desktop\VEIN.url` → 页面图标 + 左上箭头（256×256，带 alpha）；`Telegram.lnk` → Telegram 图标 + 左上箭头。
- `.url` 的站点图标取决于 Windows 是否缓存了该站点的 favicon；没有缓存时显示的是系统"网页快捷方式"图标，与 Explorer 一致。

## English summary

0.7.6 fixes shortcut icons in the file view. `.url` shortcuts are no longer resolved as if they had a file target — that produced "unsupported thumbnail" and fell back to a small type icon; the Shell is now asked for the shortcut file's own icon. Shortcut previews are composed with the Windows link arrow in the bottom-left, because `IShellItemImageFactory` never adds the overlay. The self-drawn link badge now follows Explorer's proportions (27.5 % of extra-large icons, 25 % of large, 15.6 % of medium; other sizes unchanged). Thumbnail cache versions were raised so stale images are not reused.
